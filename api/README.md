# API

`openapi.yaml` — контракт между фронтендом и бэкендом (OpenAPI 3.0.3). Общие правила (сессия, ошибки, время,
потоки ИИ) описаны в начале самого файла, по методам — в их описаниях.

## Что в нём

| Тег | Что | Экраны |
|---|---|---|
| Профиль | сессия, ключ восстановления, настройки, цель дня, статистика, уведомления | X1, X2, H1, M1 |
| Учёба | предметы, темы, уроки, «изучено», поиск | L1–L3, O1 |
| Тесты | тест по теме, ошибки, смешанный; ответы, итог, разбор | T1–T3 |
| Практика | счётчики, ошибки, карта дыр | P1–P4 |
| Пробный КТ | формат, попытка с серверным таймером, аудирование, итог, разбор | K0–K5, O6 |
| Награды | достижения, косметика, лига недели | M2–M4 |
| План и новости | план до КТ, даты, новости | N1, N2, H1 |
| ИИ-наставник | чаты, потоковые ответы (SSE), «объяснить ошибку», лимиты | I1, I2 |

## Мок

`make up` поднимает Prism на <http://localhost:4010>. Мок требует cookie `sid` с любым значением, как и настоящий
сервер: в консоли браузера на `localhost` выполните `document.cookie = 'sid=mock'` (в `web/api.js` это делает
режим разработки). Нужный статус ответа выбирается заголовком `Prefer: code=429`, пример — `Prefer: example=topic`.
Мок отдаёт примеры из схем, поэтому **примеры должны проходить схему**: если нет, Prism может упасть.

## Проверка

```
npx @redocly/cli@1.34.5 lint api/openapi.yaml --config api/redocly.yaml
```

То же запускает CI. Это же проверка, что YAML разбирается: запятая или двоеточие внутри неэкранированного текста
в `{...}` ломает пример (текст берите в кавычки).

## Как менять

1. Меняем `openapi.yaml` и пишем в PR, что изменилось и кого это задевает (фронтенд, бэкенд, мок).
2. Не ломаем существующее: новые поля — необязательные; удаление или переименование — только после согласования.
3. Пример у ответа обязателен, если без него мок вернёт бессмысленные данные.
