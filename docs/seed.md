# Формат seed (S-05)

Учебный контент — темы, разделы (уроки), общие материалы и вопросы — команда пишет сама и кладёт в `content/seed/`.
Загружает его в базу подкоманда `server seed [каталог]` (по умолчанию `content/seed`; локально — `make seed`, на
сервере — `deploy/deploy.sh` после миграций). Сервер при старте seed не грузит. Таблицы — [db.md](db.md).

## Каталоги и файлы

```
content/seed/
  english/      algorithms/      tgo/      databases/
    topics.json     темы предмета
    sections.json   разделы тем
    materials.json  общие тексты и таблицы к группам вопросов
    questions.json  вопросы с вариантами
```

Каталог — код предмета (`english`, `tgo`, `algorithms`, `databases`), предмет строк берётся из него. Любой файл может
отсутствовать. Каждый файл — JSON-массив; неизвестные поля и файлы — ошибка (опечатка не пропадает молча). Тексты —
Markdown, переводы строк — `\n`. Ссылки между строками — по `ext_id`, в том числе между файлами разных предметов
(общие материалы).

| Файл | Поля |
|---|---|
| `topics.json` | `ext_id`, `title`, `position` |
| `sections.json` | `ext_id`, `topic` (ext_id темы), `title`, `position`, `body_md` |
| `materials.json` | `ext_id`, `body_md` |
| `questions.json` | `ext_id`, `topic`?, `kind` (`single`/`multiple`), `text_md`, `code_lang`? + `code_source`?, `shared_material`?, `explanation_md`, `section`?, `listen_text`? + `listen_lang`?, `options` |
| `options[]` | `ext_id`, `text_md`, `is_correct`; позиция — место в списке |

`?` — необязательное поле. Пример вопроса:

```json
{
  "ext_id": "db-q-orders-count",
  "topic": "db-select",
  "kind": "single",
  "text_md": "Что вернёт `select count(amount) from orders;`?",
  "shared_material": "db-mat-orders",
  "explanation_md": "`COUNT(столбец)` пропускает `NULL`, поэтому 4, а не 5.",
  "section": "db-select-where-group",
  "options": [
    {"ext_id": "a", "text_md": "4", "is_correct": true},
    {"ext_id": "b", "text_md": "5", "is_correct": false}
  ]
}
```

## Проверки

Загрузчик проверяет seed целиком до записи и перечисляет все ошибки разом, каждую с файлом и `ext_id`:

- `ext_id` задан и уникален среди строк своего вида во всём seed; варианты — уникальны внутри вопроса;
- ссылки (`topic`, `section`, `shared_material`) существуют; тема и раздел — того же предмета, что строка;
- у вопросов `algorithms` и `databases` тема обязательна (без темы бывают только английский и ТГО);
- `position` ≥ 1 и не повторяется среди тем предмета и разделов темы;
- `single` — ровно один верный вариант, `multiple` — хотя бы один; вариантов не меньше двух;
- `code_lang` и `code_source`, `listen_text` и `listen_lang` задаются парами; обязательные тексты не пустые.

**Аудит банка (S-06, `content.Audit`, тест `TestRepositorySeed` в CI):** дубли вопросов по отпечатку (`Fingerprint`:
предмет, условие, код, общий материал и множество вариантов с отметкой верных — без регистра, кавычек Markdown,
лишних пробелов и порядка вариантов; ext_id и пояснение не влияют), одинаковые варианты внутри вопроса, пустые
пояснения. У каждого предмета КТ должен быть хотя бы один вопрос; нехватка до числа заданий из
`content/exam_config.json` пока только печатается — станет ошибкой, когда банк наполнят генераторы (S-04, S-07).

## Как загружается

Одной транзакцией: ошибка — и база остаётся как была. Строки сравниваются по `sum_hash`:

- `sum_hash` — sha256 в hex от канонического JSON строки: все её поля в фиксированном порядке, ссылки — `ext_id`,
  у вопроса — вместе с вариантами и их порядком (`internal/app/content`, методы `SumHash`);
- новый `ext_id` — вставка; тот же `ext_id` с другим хэшем — строка переписывается на месте (`insert … on conflict
  (ext_id) do update … where sum_hash is distinct from excluded.sum_hash`), варианты вопроса заменяются целиком;
  с тем же хэшем — не трогается;
- тема, раздел или вопрос, пропавшие из seed, помечаются `retired_at`; вернувшиеся — снова в обороте
  (`retired_at = null`). Ничего не удаляется. Общие материалы не выводятся: у них нет `retired_at`.

Отчёт — по каждому виду строк: добавлено, изменено, без изменений, возвращено, выведено. Повторная загрузка того же
seed ничего не меняет («изменений нет»).

**Правка вопроса** (правило из [db.md](db.md)): опечатки и пояснения — на месте под прежним `ext_id`; существенная правка
(условие, варианты, верный ответ) — новый `ext_id`, а старый вопрос просто убрать из seed: он будет выведен из оборота
и останется в истории попыток.

**`ext_id` варианта не менять.** Попытки хранят выбранные варианты по их `ext_id`: если при правке вопроса у варианта
сменился `ext_id`, в разборе старых попыток выбранный ответ пропадёт. Менять можно текст варианта, а не его `ext_id`.

**Пустой seed не загружается.** Если в каталоге нет ни тем, ни вопросов (неверный путь, пустой каталог в образе),
загрузчик отказывает: иначе одна загрузка вывела бы из оборота весь контент.
